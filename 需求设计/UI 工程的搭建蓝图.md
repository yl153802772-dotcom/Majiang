# 《赛博雀神（暂定）》局内交互与UI系统设计文档

**文档版本**：V2.0 (基于最新禅意版 UI 原型与 PRD V7.2)
**面向对象**：客户端主程 / UI 开发 / 交互设计
**文档目标**：指导 Cocos Creator 3D 工程的 Canvas 节点树搭建、UI 组件数据绑定、商业化坑位预留及核心事件总线设计。

---

## 一、 界面节点层级规划 (UI Z-Order)

建议在 Cocos `Canvas` 下严格按以下层级建立根节点，确保多层叠放不出现穿透 BUG：

1. **`Layer_Background` (Z=0)**：
   * 承载最底层的静态背景图（如国潮/禅意风场景）。
   * 环境粒子特效（如背景中微弱飘落的花瓣/光斑预制体）。

2. **`Layer_PlayArea` (Z=10)**：
   * 游戏核心桌面区，包含所有麻将 Block（单块、双块）的父节点。
   * Block 的层级依照算法设定的 `Layer 1~3` 动态调整其自身的局部 Z-order。
   * 承载胡牌大招时的“目标锁定”高亮特效与消除轰炸粒子。

3. **`Layer_HUD` (Z=20)**：
   * 局内常驻 2D UI 控件层。
   * 包含：顶部数据看板、凑副区（计番槽）、底部底槽、底部道具栏。

4. **`Layer_Effect` (Z=30)**：
   * 全局 UI 飞行与转场特效层。
   * 包含：麻将从桌面飞入底槽、从底槽组合后飞入凑副区的**拖尾飞行动画节点**（使用独立的相机渲染或坐标映射，防止被其他 UI 遮挡）。

5. **`Layer_Popup` (Z=40)**：
   * 全局弹窗层。
   * 包含：暂停菜单、规则/帮助说明面板、游戏失败/胜利结算面板、激励视频补给确认框。

## 二、 核心 UI 组件详细拆解与绑定

### 2.1 顶部数据与控制栏 (Top HUD)
* **UI 元素**：
  * 左侧：关卡标题（第 1 关）、剩余牌数面板（剩余 48 张 + 进度条）。
  * 右侧：暂停按钮、帮助按钮、用时（00:00）、星级积分（0）。
* **数据绑定与更新**：
  * `GameManager.remainTilesCount` ➔ 实时驱动“剩余 X 张”文本，并按 `剩余数 / 初始总数` 比例更新绿色进度条（`cc.ProgressBar`）。每次触发组合消除后更新。
  * `GameManager.playTime` ➔ 格式化为 `MM:SS` 每秒更新。

### 2.2 凑副区 / 计番槽 (Combo Area)
* **UI 元素**：文本“凑副 0/4”，以及标有 1、2、3、4 的四个空心槽位。
* **节点逻辑与动态挂载**：
  * **副牌填充**：底槽触发“吃/碰/杠”后，UI 表现为该组牌的缩微贴图飞入对应的 `Slot_X` 中，同时“凑副 X/4”文本递增。
  * **隐藏的第 5 槽（将牌槽）**：*注意，原型图中仅画出 4 槽，这符合日常凑副状态。* 当文本达到 `4/4`（进入听牌状态）时，程序需在第 4 槽右侧动态 Instantiate（实例化）出一个特殊高亮的**将牌槽**，等待最后两张将牌飞入触发大招。大招触发瞬间，整个凑副区清空。

### 2.3 操作底槽区 (Bottom Slot)
* **UI 元素**：文本“底槽 0/7”，以及 7 个等距排列的方格。
* **组件特性要求 (关键)**：
  * **单双块占位映射**：单块 UI 占 1 格宽，双块 UI 必须完整占据连续的 2 格宽。
  * **自动左压缩动画**：利用 `Layout` 组件（或自写插值位移脚本），任何牌入槽或消除后，槽内剩余元素必须以 `0.1s` 的滑动过渡动画向左侧靠拢压缩，禁止瞬间闪现。
  * **警报反馈**：当占用格数达到 6 格时，整个底槽的绿色外框应切换至“呼吸红光”警报状态。

### 2.4 道具商业化区 (Props Area)
* **UI 元素**：“道具”栏目标题、[▶ 补给] 按钮、四大核心道具（磁铁、移出、洗牌、翻面）及对应的绿色 [+] 按钮。
* **商业化（IAA）逻辑封装**：
  * **道具状态**：每个道具独立维护库存 `count`。`count > 0` 时高亮可点；`count == 0` 时图标置灰。
  * **[+] 与补给按钮**：点击触发激励视频 API (`AdsManager.showRewardVideo()`)，成功回调后发放对应道具奖励。
* **道具功能绑定预留**：
  1. **磁铁**：调用 `PropManager.useMagnet()`，检索场上可与底槽配对的块并强制消除。
  2. **移出**：调用 `PropManager.useRemove()`，将底槽最左侧占用（单块或双块）弹出至桌面空白层级，底槽左压缩。
  3. **洗牌**：调用 `PropManager.useShuffle()`，重置桌面层 Layer 1~3 的伪随机坐标。
  4. **翻面**：预留。可用于直接发放一张“万能赖子牌”入槽。

## 三、 核心交互事件总线 (Event Emitter)

建议采用观察者模式（Event Target）解耦 UI 与状态机逻辑。所有判定务必在 100ms 内完成，动画仅做视觉追随。

| 事件名称 (Event Name) | 触发时机与载荷 (Payload) | UI 层监听行为 |
| :--- | :--- | :--- |
| `EVENT_BLOCK_CLICKED` | 玩家点击有效 Block。携带 `blockId`。 | UI 层不直接移动牌，等待逻辑层计算结果。 |
| `EVENT_SLOT_UPDATE` | 底槽数据数组变更。携带最新 `[blockIds]`。 | UI 层根据数组重新排列底槽节点，执行左滑过渡动画。 |
| `EVENT_SLOT_REJECTED` | 底槽满或虚拟入槽失败。 | 桌面被点击的牌播放“轻微左右抖动”并弹回原位，提示空间不足。 |
| `EVENT_COMBO_MATCHED` | 触发吃碰杠。携带 `comboType, targetSlotIndex`。 | 底槽对应的牌执行飞向计番区 `Slot_X` 的贝塞尔曲线动画。 |
| `EVENT_ENTER_TENPAI` | 完成 4 副牌。 | 动态生成第 5 槽（将位）；激活桌面上所有可用单块的“听牌高亮滤镜”。 |
| `EVENT_ULTIMATE_READY`| 将牌达成。携带被锁定的 `targetGroupIds`。 | 播放大招全屏特效，被锁定的 Block 闪烁后销毁。清空计番区 UI。 |
| `EVENT_GAME_OVER` | 胜利或满槽无解。携带 `isWin`。 | 禁用全局 `Touch` 事件，延时 1 秒弹出结算面板。 |
