## 1. 选择唯一入口

- 普通项目可用FrameworkBootstrap；现有游戏用GameBootstrap；独立示例用FrameworkDemo。三者不得同时驱动同一个App。
- App.init/start/dispose须await；项目模块声明dependencies。依赖resources的模块须先于资源层退出，不能在App.dispose后再清理活动owner。
- UI/音频根节点显式传入，持久化与普通场景的父子树寿命由项目确定。不搜索Canvas名称或修改全局设置以修复局部布局。

## 2. 统一暂停

创建一个PauseController交给可选RuntimeLifecycle，将其作为App模块注册；若涉及音频/存档，声明audio/存档模块依赖。仅在项目已经配置并批准存档时传入flush回调，不能直接调用未init的SaveManager。

```ts
const runtime = new RuntimeLifecycle();
await App.Instance.init({
    uiRoot,
    modules: [{ name: 'runtime-lifecycle', module: runtime }],
});
await App.Instance.start();
const releaseHelp = runtime.pauses.hold('help');
// 帮助页隐藏/销毁时执行；不会撤销后台或其他弹窗的暂停。
releaseHelp();
```

上述代码为已具备uiRoot的项目接入片段。GAME计时与可选音频由RuntimeLifecycle协调；项目自己的update、输入、物理和动画需消费同一pause状态，不能假设框架暂停GAME定时器等于整个引擎或Domain自动暂停。
UI显示寿命用showScope登记hold返回的释放函数；背景恢复只撤销background，不能直接resume所有系统。退出不能用清空全部暂停原因替代释放自己的租约。

## 3. 统一坐标

ViewportService.start前，项目已明确Canvas/相机及设计尺寸。subscribe变化后，applyContent到未额外缩放的内容根、applyCamera到全屏正交相机；UI与3D世界单位按同一个unitsPerPixel约定。
输入使用与映射匹配的坐标：getUILocation对应snapshot.ui，物理屏幕点对应snapshot.pixels；fromViewport得到设计坐标。先判断contains再执行命令，保留独立的逻辑遮挡规则。
不把screen.windowSize再单独除DPR后与物理viewport混用，不用拉伸解决遮挡图问题。EXACT_FIT非等比缩放不受共享投影支持；先由项目选择等比策略。
设备安全区与微信胶囊分开：项目提供额外reservedTop设计单位，避免重复扣除safeArea.top。背景可铺满，交互内容应落入安全矩形。

## 4. 资源与平台

- acquire必须有句柄或有效Scope；缓存keep界面只在destroy结束实例资源，隐藏仅结束showScope。
- 远程Bundle通过BundleManager.register配置，加载前冻结来源/版本。卸载用ResManager.releaseBundle，检查false/异常；所有别名和活动owner释放前不能切版本。资源分包不再额外重复调用原生代码分包接口。
- SubpackageLoader.load可传scope/timeoutMs/onProgress。失败重试由调用方决定；未知平台能力不能模拟成功。dispose会立即拒绝本服务消费者，底层不可中止请求继续记录为物理pending直到回调。
- HTTP默认0重试；GET可显式选择最多2次。写请求不得自动重试；token/endpoint在单次逻辑请求内冻结，退出取消Scope。
- App默认启用PlatformRuntime事件服务，可用platformRuntime:false关闭。低内存仅回收闲置内存资产，绝不强清活动资源或本地存档。磁盘LRU须显式调用；不新建第二套下载磁盘缓存。

## 5. 复用与产物检查

在项目根执行，无需npm install：

```text
npm run check
npm test
npm run check:game
npm run test:game
node tools/framework-release.mjs audit
node tools/framework-release.mjs export build/<尚不存在的目录> --examples
node tools/framework-release.mjs build build/<Web包目录>
node tools/framework-release.mjs build build/<微信包目录> --wechat
```

可加`--max-bytes=<正整数>`检查未压缩产物目录预算；这个预算必须来自本产品实际目标，不能当作微信平台包体限制。工具静态通过仍显示productionReady:false与deviceAcceptance:not-verified。
示例须运行在独立Scene，正式游戏产物按项目配置排除示例内容。导出包包含独立README和framework-manifest.json；Creator首次导入可能规范化新meta的files/userData，必须核对UUID与源码，不能将正常导入与源码篡改混为一谈。
