## 2. 编码边界

- 业务只进 Game；Domain 和 Application 保持纯 TS，Config 数据与表现参数分开。
- 一次命令一次事务；配方、虚拟入槽、终局只写一套权威算法；测试构造预期不得复用被测算法。
- 只读快照/事件驱动 View；物理、Tween、UI 和碰撞不能决定规则、清牌或奖励。
- 先通过纯规则/会话测试，再接场景；不能用固定推荐路线脚本代替真实可玩的选择逻辑。
- `strict` 保持开启；不用 any、`@ts-ignore`、宽泛类型断言或伪引擎声明逃避错误。
- Map/Set/iterator 快照用 `Array.from()`，不写 `[...map.values()]`。该工程已真实遇到 Creator 宽松展开转译运行错误；Node 测试通过仍不够。
- 公共类型明确输入、输出和拒绝原因，事件携带 sessionId/revision/eventId；所有 effect 处理过期与去重。将牌必须保持单块/双单块的受约束联合类型，不能退化为无约束数组。pairCleanup 只按真实 GroupID 找同组伙伴，不按牌面跨组、不硬编码，不重复记账。
- 不在每帧扫描配方、创建材质或反复加载资源。Mesh/Material/文字/效果替身有明确所有者和硬上限。
- scope/订阅/计时器/刚体/节点都可取消、可回收；BoardView 自建 Mesh/Material 由场景级 owner 明确释放，正常重开复用，退出/启动失败/重试后释放；一个清理步骤报错不得阻断其余收尾。异步失败不能被空 catch 吞掉并显示成功。
- 构造时每次取得所有权立即登记清理，创建 View 前先拥有其节点子树；构造失败调用 LifecycleScope.rollback，保留原始与清理错误。不得等构造函数返回后才登记唯一清理。启动/重试使用代次检查，退出后的 Promise 不得重新启动、挂载或展示面板。
- 不擅自改 Framework、Main.scene、package、tsconfig、引擎设置或其他批次文件。实际缺口先报路径/复现/影响，请负责人新增授权。
- 不为“后续可能需要”新建存档、网络、广告、ECS、多关卡或正式美术系统。

## 3. Cocos 实施约定

当前 Main.scene 已接入唯一 GameBootstrap 并可玩；FrameworkBootstrap 与框架自检是历史接入基线，不得再并行启用第二套 App。后续任务默认不改框架源。
已有资产 `.meta` UUID 保持；新 TS/目录/场景资产生成对应 metadata 并检查唯一性。不得把压缩脚本类型 ID 猜出来直接写进场景；用编辑器生成，或按本机实际注册值验证。无法生成/验证就报告，不能声称场景可运行。
程序化白膜是早期第一版默认方案。当前已批准的GAME-UI-01允许使用现有UIRuntime贴图与真实Prefab，文字仍为引擎原生Label，桌面仍为真实轻3D牌；替换旧UI重复绘制，不能把旧白膜限制误当成禁止本批已批准美术融合。其他批次只按各自已批准范围使用资产，不自行引入新模型、字体、shader或npm包。
Cannon 是 Cocos 内置后端，在 G06 明确批准项目物理配置后启用；不要执行依赖安装。此前相机/Layer 配置改动也必须列进任务范围。
不要直接改 library/temp/build 来“修源码”。构建会生成项目派生文件，必须在任务单列明允许的派生目录。
真实引擎失败不能只看退出码：本机 Creator 成功退出码为 36，但日志仍要检查 `error`、`Missing class` 和实际启动画面/控制台。内部诊断必须经构建期条件隔离；release 构建无参数或带 `?r01diag=1` 都不得创建 `window.__R0__` 或开放 restart/reinit/failStartup；只有 debug 构建在显式参数下开放。不能把默认关闭/只读属性当作发布隔离。
微信 AppID、账号、安全接口或工具初始化缺失时停在证据边界，不改全局设置绕过，不声称真机完成。

## 4. 验证义务

每批至少对照对应验收行实际执行可用检查；不能把旧框架 55 项通过算作新增游戏通过。

现有命令：

~~~sh
cd /Users/liang/Projects/Majing
npm run check
npm test
~~~

`npm run check` 类型检查包含 assets 全部 TS，但目前只对 Framework 做边界/展开扫描。`npm test` 只跑 tests 根目录，不发现 tests/game。
`npm run check:game` 与 `npm run test:game` 已存在，分别执行分层/规则静态检查与 tests/game 测试；必须与上面两项一并运行，不改测试发现范围以掩盖问题。
Game 检查器至少用临时内存 fixture 验证：纯规则导入 cc/Framework/Application（Domain 反向导入）、规则随机、非数组 iterable 展开确实被拒绝；同时证明合法纯 TS 被接受。不得把负例永久放入生产 assets 来污染构建。
本批开始/结束均核对实际文件清单；Codex 独立复核白名单外文件与框架/既有 .meta 的哈希变化。清单和提示词不是权限控制，不能假设 Harness 能强制限制路径。
游戏测试实际命令：`node --import ./tests/register.mjs --test tests/game/*.test.mjs`；加载器使用 cc mock 或依赖注入的故障测试必须标为单元验证，不是实际引擎运行。
当前内容版本为 `888-v3`，契约 V2.3；R0 的 2.6ms 为旧实现记录，R0.1/R0.2 必须从 TouchEnd 回调入口重新计时并分别在 release 包取证。release User Timing 采样必须有界（每局 256 条），换局 reset、退场 dispose，只清本模块名称；不支持/抛错安全跳过。当前已验证运行时是 Node 24.15.0，加载器使用 registerHooks；其他执行环境先确认现有 Node 能力，不能默认兼容、擅自升级或安装运行时。
R03 起，clear 失败暂停写入且不得重置额度，只有命名清理成功才恢复；measure 抛错也暂停，防止先写入后抛错的无限重试。测试必须覆盖多次失败 reset、恢复清理和 dispose 后旧回调，不能只测“不抛错”。
Web、Cocos、微信工具、真机各自报告，缺一种就写未执行/受阻。提供构建命令/产物路径和日志，不只贴“success”。
无法运行时写清工具缺失、已做的替代静态检查、未覆盖风险，不伪造结果，也不自行安装工具。

## 5. 失败、歧义与框架缺口

已批准范围内的实现 Bug/测试失败可以修复并复测，保留失败现象与最终结果。只读审查发现问题不得顺手修复。
若修复需超范围、改规则、改公共接口、切物理后端或破坏通用 API：暂停相关分支，报告“现象/复现 → 原因证据 → 影响 → 最小建议与新增路径/风险”，等待负责人批准。可继续无冲突的已批准工作。
禁止通过删测试、放宽断言、改固定关答案、关闭 strict 或永久禁用 3D/物理把失败变成通过。
架构冲突和无法唯一解读的产品规则不自行拍板；本 V2 明确的比较器/坐标/物理边界属于本轮架构基线，不重复制造隐含版本。
