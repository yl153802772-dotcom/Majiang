## 1. 依据、决定与范围

已确认需求：根目录 `需求设计/01_需求定稿/MVP_FINAL.md` 的七槽固定关；负责人 R0.1 明确将牌支持同牌双块或两个相同单块、稳定满七立即失败；R0.2 增加双块将同组残块清理与构建期诊断隔离。全 2D UI、2D 牌桌视觉、轻 3D 牌块效果/物理、白膜及引擎文字、V2 必须完成首版 MVP Demo 的边界不变。

下列是本架构采用的工程决定，不新增产品功能：

- 纯 TypeScript 规则内核 + 单写入会话 + Cocos 表现适配，不引入 ECS、DI 容器或第三方库。
- 物理只作用于短命视觉替身；真正的 Block 位置/去向由规则状态决定，不能散落成随机牌堆。
- 使用 Cocos 自带 Cannon 后端执行少量 BoxCollider + RigidBody 表现；不是安装 cannon npm 包。本轮不修改物理配置，启用安排在专门授权的接入批次。
- 桌面是平面背景，不做 3D 桌子、自由相机或环境场景。几何体牌块具备真实厚度和短时刚体运动，而非纯 2D 假动效。
- 底槽、计番区和将牌提示是同一逻辑牌块的 2D 缩略表达；移动/消除时可播放不可交互的 3D 替身，不拆分双块。
- 不以浏览器通过代替 Cocos、微信开发者工具及真机；不以“架构已定型”代替负责人验收。

Demo 的完成定义：固定关可实际触摸游玩，四副一将和大招完整可见，能通关/失败/重开，所有 TC-01～TC-17 及 V2 表现边界有证据，微信工具和至少一台手机通过。仅交规则库或能构建的空场景不算完成。

不做正式美术、音效、广告、联网、存档、排行榜、养成、道具、撤销、洗牌或随机多关卡。轻 3D 不是增加物理玩法。

## 3. 启动、关闭和资源所有权

### 3.1 唯一入口

当前 `assets/scenes/Main.scene` 已接入项目 `GameBootstrap`，运行时构建白膜游戏场景，既有场景UUID保留；不要重新并行启用FrameworkBootstrap或第二套App。
GameBootstrap 在 `App.init` 之前一次性提供 `AppOptions.modules`，注册 `game` 模块，依赖 `resources`、`timers`、`presentation`。不要等 App 已初始化再注册。

当前实现流程：构造场景/相机 → 创建并校验GameSession → 预建共享Mesh/Material、文字与UI → App.init/start → 挂载快照和订阅 → 开启取牌。任何中间失败走所有权回滚及错误/重试界面。
GameBootstrap 是唯一 `App.update` 帧驱动；物理由引擎自身步进，不再手动重复模拟。
本Demo单场景，不创建跨场景常驻游戏节点；onDestroy停止唯一驱动，捕获/等待App.dispose触发的模块清理，再释放本实例场景/错误UI，迟到启动不得重新挂载，不留下未处理Promise。
启动失败显示 2D 错误/重试状态；重试必须先完整释放失败实例再重新初始化，不能复用已关闭 Scope。清理按步骤隔离，一个监听/节点/效果/资源释放报错不得阻断其余收尾。内部诊断必须使用明确开关，正式发布配置关闭全局诊断和逐次 console 日志。

### 3.2 三层寿命

- App/场景 Scope：共享几何体、共享材质、UI 根、字体可用性检查、引擎事件监听，以及唯一 GameSession 控制器和它的长期订阅。
- Round Scope：当前 sessionId 的局内计时、视觉对象和临时订阅；不拥有 GameSession 本体或它的长期订阅。
- Effect Scope：一次飞牌/大招的 Tween、刚体、替身、超时收尾。

GameSession 对象寿命等于场景寿命，sessionId 仅表示一轮，不表示重新分配控制器。
重开由同一个 GameSession.dispatch(restart) 原子重置规则并分配新 sessionId；GameRoot 先结束旧 Round Scope/Effect Scope，再建立新 Round Scope 并渲染。旧 Round Scope 即使清理报错也必须继续其余收尾，报告错误并按新快照恢复；不能因此 dispose 会话控制器。
重开保留场景资产、GameSession 和场景级订阅，不重复初始化 App；只有退场才解除长期订阅并 dispose GameSession。事件局号过滤和效果去重按新 sessionId 切换。
退场先停止输入 → 取消效果/禁用刚体和监听 → 回收/销毁节点 → 销毁自建 Mesh/Material → 归还资源句柄 → 关闭 App。
每次清理可重复调用；一个收尾异常不能阻断其他对象清理。

白膜初版优先程序化生成节点/几何体及共享纯色材质，不创建无用途的 Prefabs/Textures/Audio 目录。
同一 Mesh 和 Material 不按每次触摸新建；每种高亮状态共享预建材质，不能修改共享材质意外染色其他块。
动态创建的 Mesh/Material 由场景显式 destroy，不能当作 ResManager 已代管；若将来改为资源资产，必须 acquire/Scope 管理。
牌面 Label 使用引擎字体，不下载字体或美术。中文万/筒/条必须在真机读得清，缺字是失败，不可静默换成另一套玩法图案。

## 4. 领域模型和不变量

采用显式 BlockID/GroupID，不存 Node 或 Collider。关键类型见 `需求设计/02_架构与接口/MVP_V2_CONTRACTS.md`。

- 全关 48 张、32 Block、16 Group；每种牌面不超过 4；双块一个实体。
- Group 的两块必须同层、恰属一组；任一块被玩家取走后该组永久 broken。
- Block 的逻辑位置为 board/buffer/meld/pair/removed；buffer 只存 BlockID 顺序，占位求牌数和。
- 计番区上限四副，完整保存每副全部牌和 chi/peng/kong 类型；杠是一副，不误算为固定三张。
- 将牌始终是两张相同牌：一个同牌双块独立成将（1 个 BlockID），或两个相同单块成将（2 个 BlockID）；顺子双块不能作将。四副一将共使用 9 或 10 个不同 BlockID，不允许 Block 复用。双块将触发同组残块清理：按真实 GroupID 找同组另一个 Block，若在 board/buffer 则整块清除；该残块不计入手牌/目标/番型。
- 状态保存已消费牌去向和不可变快照；不得因清空计番区丢失牌守恒审计。
- 所有稳定快照 buffer ≤7、紧凑无空洞、无重复 BlockID/目标、没有被移除块仍可选。
- 领域状态仅 GameSession 事务提交写入。对外 DTO 深拷贝并 deep-readonly；开发测试冻结以发现越权写入，不每帧深冻结。
- sessionId 是由启动层注入的单调唯一 ID，不用随机数；revision 仅接受命令时递增，拒绝不改状态。

固定关所有表格只在 `Config/Level888.ts` 存一份。推荐命令另存 `RecommendedSolution888.ts`，不能让实现反过来“猜测”配置或按目标答案硬编码通关。

## 5. 命令事务与裁决定型

稳定 phase 只有 Collecting/Tenpai/Won/Lost。胡牌快照、大招结算是同步事务内有序步骤，通过事件保留轨迹，不作为等待动画的稳定输入锁。

SelectBlock(sessionId, blockId) 的执行次序：

1. 校验局号、非终局、块在 board、显式 blockedBy 满足；事务忙时拒绝 `busy`，不无限排队。
2. 构造隔离草稿；若加入后超过 7，仅模拟“该新块能立即参与配方/将牌”才能放行。
3. 取完整块、标记本组 broken、赋单调 enterOrder；按以下比较器结算。
4. 形成第四副时立即转 Tenpai 并检查既有合法将牌（同牌双块或两个相同单块）；胡牌时冻结四副一将、完整大招目标及 `pairCleanup` 残块清单。将牌候选先于普通副牌；未满四副不生成将牌候选，桌面未取的同牌双块不会自动胡。残块只由真实 GroupID 推导，不按牌面/坐标硬编码；不改变手牌、目标或番型。
5. 完成 target 清除、将牌/副牌清除、pairCleanup 清除、底槽压缩、组状态与稳定扫描；数据层立即清目标组、解锁遮挡，保留未消费底槽。
6. 检查通关/稳定满七失败、不变量，原子提交一个新 revision。
7. 同步通知最新快照，再发本事务按序视觉事件；结束 TouchEnd 指标采样。

任何规则异常在提交前回滚草稿，不发成功事件。提交后的 View/事件监听错误只报告表现故障并从最新快照恢复，不能将已提交命令谎报为逻辑回滚。通知阶段也保持命令忙标志，监听器不得递归写规则；用户下一次真实触摸按新快照执行。

### 5.1 唯一比较器

需求明确：新块相关组合优先；听牌将牌优先；旧候选最后入槽 → 底槽最左 → BlockID 字典序。
工程补全：听牌优先将牌（同牌双块独立将和两个单块将使用同一候选类型与比较器），再比较组合是否含本次新块；其后按组合所有参与块 enterOrder 的 `(max,min)` 降序、槽索引排序元组升序、ID 排序元组升序。第四副时的“最新合法将牌”用同一比较器，剩余同序条件相同。
每次移除/胡牌重置后重新计算候选与当前 phase；不能沿用旧候选缓存。
最多 32 块，有限扫描即可；不得按 Map 插入顺序、动画完成顺序或碰撞顺序决胜。

### 5.2 虚拟入槽和失败

模拟内部最多 9 张（原 7 + 双 2）；公开快照永不出现第八格。越界资格必须由新块自身直接参与合法组合提供，旧块无关组合不兜底。
拒绝 `insufficient-space` 时牌仍在桌面、组未破坏、revision 不变，只提示空间不足。
失败检测调用与真实选牌相同的可入槽模拟，不另写近似判断；只枚举当前可点击且未锁定 board 块。
严格失败（R0.1）：一次合法取牌完成组合、瞬胡、大招和稳定扫描后，底槽稳定占满 7 格且无合法组合，立即 Lost；不再要求“桌面无可救输入”。失败在同一事务提交，停止取牌，失败面板在下一个可渲染帧出现，不等待飞牌动画；失败事件只发一次。未满 7 格但无可行动作仅诊断 Stalled、保留重开。

## 6. 番型、目标和非阻塞一致性

清一色 5 组 > 碰碰胡 2 组 > 平胡 1 组，不叠加；杠的第四张计入花色判断。
目标只取仍 intact 且两块都在 board 的组，按该组固定 layer 降序、GroupID 字典序；规则“可见层级”采用剩余逻辑层，不用相机遮挡/像素可见性。关卡校验要求组内同层，所以层级没有两块分歧。
blockedBy 限制玩家输入，不额外限制大招完整组资格。目标不足清除全部合格组，不补组、不降番、不保证非推荐路线可解。

逻辑上大招目标在同一事务中即 removed，下一输入已处在下一轮；视觉保留的是不可点击替身。
原需求“动画中目标锁定”由目标离开可选集合实现，不等待刚体静止后才解锁下层。
每条事件包含 sessionId/revision/eventId，effectId 在一局内唯一，去重重复消费；旧局事件直接丢弃。
多个大招视觉可重叠，目标不能重复选择；合并/缩短视觉不合并两次逻辑快照。
缓冲容量、清牌、胜负绝不在动画或 collision 回调执行。动画失败/超时清替身并按快照重绘，不能卡局。
终局即禁止取牌；结果 UI 在视觉完结或最多 1.5 秒后出现，也可直接取消剩余效果显示，重开始终有效。

## 7. 2D UI + 2D 牌桌 + 轻 3D 牌块

### 7.1 场景结构与相机

~~~text
Main
  GameBootstrap                 唯一 App 帧驱动
  BackgroundCanvas + BgCamera   2D 平面牌桌、纯色/Graphics
  TableWorld + TileCamera       正交相机；真实 3D 牌块与特效替身
    LiveBlocks                  固定位置、有厚度、无动态刚体
    EffectProxies               有界、短命刚体；无输入
    EffectFloor                 仅替身可碰撞的静态平面
  OverlayCanvas + UiCamera      全部按钮、引擎文字、2D 底槽/计番区/结算
    BoardInput                  单一触摸入口和投影命中表
    BoardLabelsAndHighlights    非输入节点；牌面字与描边
    Hud / Buffer / Melds / Toast / Result / Diagnostics
~~~

三台相机分别只看自己的 Layer；不新增 RenderTexture、多重采样特效或后处理。
背景相机先清颜色/深度，牌相机随后仅清深度，UI 相机最后仅清深度，不清掉之前颜色。
3.8.8 本地引擎 `render-window.ts` 按 priority 升序排序，约定 background=0、tiles=1、overlay=2；官方说明中优先级文字存在歧义，实施必须用三层色块遮挡探针在 Web 与微信实测确认，不照抄旧版本文章。
隔离用户 Layer 的配置改动仅限接入批次；禁止 UI 相机重复渲染 Mesh 或牌相机渲染全屏不透明 UI。

牌相机固定正交，朝向桌面法线；静态牌体使用轻微倾角/侧面颜色展示厚度，不倾斜整张桌面。禁用真实阴影、反射探针、PBR 贴图和复杂灯光；先用共享纯色材质或简单顶点色。
牌块按逻辑 layer 映射渲染深度，厚度/倾斜范围必须小于相邻层间距，避免穿插和排序颠倒。绘制 Z 不可回写逻辑 layer。
初始工程参数：世界 XY 为桌面平面、+Z 朝相机；相机位于 Z=10 朝 -Z，单/双块宽 0.64/1.32、高 0.88、厚 0.12，层间距 0.35，静态 X 倾角约 6°。这些是可调白膜参数，不改变规则显示框；必须验证全部可见牌面和边缘命中。

### 7.2 统一坐标与输入

设计坐标遵循 `需求设计/01_需求定稿/MVP_FINAL.md` §7.2：左上原点，中心坐标；Canvas 居中局部值 `(x-360, 640-y)`。逐块映射是唯一布局，汇总行不另给 Y。
`TableProjector` 是设计坐标、UI 局部、屏幕和世界坐标唯一转换入口。正交相机与 UI 使用同一可见矩形/viewport/适配策略；不得用设备物理分辨率直接当设计像素或在多处手乘 DPR。
建议设计像素到世界单位 100:1（单牌 0.64×0.88），只改变世界缩放，不改变 64×88 的输入设计框。
注意本机 3.8.8 的 `orthoHeight` 在正交矩阵里表示上下半高：全高 12.8 世界单位时对应 6.4，不能误设为 12.8 再将所有牌缩小一半；屏幕适配后用实际可见全高重新计算，并以投影往返探针验证。
适配使用安全区域内等比 fit：`s=min(可用宽/720, 可用高/1280)`，内容矩形居中，空余为背景；UI 与牌相机指向同一内容矩形。所有量先由引擎换到同一坐标单位，不把 Touch 的 UI 坐标再当物理屏幕坐标乘一次 s。TableProjector 封装引擎转换，其他模块不自行拼公式。
设计上部 0～120 放状态，牌区 120～800，计番区 840～960，底槽 980～1130，重开/提示 1160～1280；实际短屏统一 fit 缩放并扣安全区，不删行或改规则坐标。本批沿用 R0 的“计番在上、七槽在下”布局。

BoardInput 在 TouchEnd 取得设计点，从快照可点击块中过滤矩形命中，重叠时 layer 高者优先、再 BlockID 字典序；命中后提交一个完整 BlockID。点击开始与结束移动超过 12 设计像素视为滑动取消（即使没有 touch-move 也必须用终点比较）；多指只响应首个有效触点，抬起/取消后解除。手势记录所属 sessionId；重开/换局/暂停/终局必须取消旧手势，松手时若局号或快照已变化不得提交。
结果面板按其 UI 优先阻断 board；普通文字、描边和所有替身关闭输入拦截。遮挡只按 blockedBy，不因透明节点/物理射线增加隐藏输入规则。
桌面静态牌面文字采用 2D Label 投影到每张牌面中心，轻微倾角下仍朝向屏幕保证识别。根据固定层的投影覆盖裁掉/隐藏被上层牌面挡住的下层文字，不能让下层字浮在上层白膜上；这只是显示裁剪，不改变 blockedBy。用逐块截图探针验收 B05/B11 等重叠位置。
飞行替身文字可随投影移动；大角度翻转时隐藏牌面文字显示白背，不做文字透背。UI 缩略图始终保留已提交状态，不把飞行替身当实际未入槽牌。

### 7.3 轻量物理的明确边界

常驻桌面牌块固定在配置坐标，无需为 32 块持续跑动态刚体。选中后的飞牌由可取消 Tween/解析轨迹保证入槽反馈；底槽逻辑与 2D 缩略图同步立即更新。
组合/大招取对应整块的 3D 替身，挂一个 BoxCollider 和一个动态 RigidBody，进行短时抛起、反弹/轻翻转；双块是更宽的一个刚体和根节点，可以有两个视觉子牌，但不可分离两套运动/回调。
只启用 PROXY ↔ FLOOR 碰撞，禁用 PROXY ↔ PROXY 与真实牌碰撞；地板无可交互含义，不制造牌堆玩法。刚体反馈只用于视觉收尾，不决定组合。
Cannon 是小规模 Box 刚体的首选工程方案，不宣称最快；Builtin 不支持这里所需的动态刚体。若设备兼容/包体不满足，报告证据后单独批准后端切换，不偷偷安装替代库。
采用引擎自动固定步进：目标 1/60 秒、最多 2 子步/帧，不补偿后台经过的墙钟时间。默认重力、冲量、阻尼作为表现参数集中配置；无须跨设备轨迹位级一致，但规则回放必须一致。
最多同时 12 个动态替身；一次清 5 组最多 10 Block 可以完整表现。超预算保留整块单位，结束最旧视觉或用无刚体短轨迹，不排无限队列、不漏逻辑事件。视觉总体并发/降级计数可诊断。
单次物理替身最长 0.9 秒，所有效果最长 1.5 秒后强制收尾。归还前禁用刚体、清线/角速度、监听、绑定 ID、Tween 和姿态，再重新激活；每次租借生成新的 effect Scope。
暂停后台时屏蔽游戏输入、冻结/取消视觉和物理步进；恢复按当前快照重绘，不瞬间执行几十次追赶步。GameBootstrap 统一持有监听，退出归还此前物理设置；不要分散多组件争抢 PhysicsSystem 状态。
允许低配档减少并发和翻转，不允许隐藏所有 3D 或永久关闭物理后声称达到正常档 Demo。正常档 Web、微信工具和真机都要出现真实刚体反弹证据。

## 8. 性能和故障预算

需求硬指标：TouchEnd 回调入口 → 坐标/命中 → 规则事务 → 快照提交 → 同步渲染通知结束，每次 <100ms；计时必须从回调入口开始，覆盖命中、拒绝提示、失败和大招输入。动画/下一帧 GPU 完成不在此区间，但不能将耗时 View 同步更新排除。只测配方函数不合格。
用注入单调时钟采样，采样不上报网络；记录样本数、p95、max、超标命令/局号/设备环境，不仅报平均值。
Release 的 TouchEnd User Timing 由场景级 `TouchPerformanceRecorder` 承担：每局最多 256 条、换 sessionId/重开 reset、退场 dispose；只清本模块固定名称，不调用无参 clearMeasures；采样/清理不支持或抛错时安全跳过并记录状态，不改游戏调用链。BoardInput 的完整计时口径和其 256 条有界样本不变。
R03 加固：clear 失败不得重置额度，暂停写入直到命名清理成功；measure 抛错也暂停，防止平台先写入后抛错造成无限重试。状态包含 suspended/clearFailures，dispose 后旧回调不写。场景构造先拥有独立 UI/3D 子树，再登记逐项资源；部分构造失败复用 LifecycleScope.rollback 逆序清理。启动/重试失败均回收整套自建场景；即使 overlay 未创建，也尝试独立错误 UI。退出后的启动 Promise 通过代次检查阻止重新挂载。

工程预算（目标，不是已测值或新增产品玩法）：

| 项目 | 首轮预算与处理 |
|---|---|
| 真实桌面实体 | 固定 32 Block；48 个牌面字；不每帧重建节点 |
| 物理 | 动态替身 ≤12，静态效果地板 1，原牌不挂动态刚体 |
| 材质/Mesh | 共享有限预建集合；禁止每次点击 new Material/mesh；BoardView 自建 Mesh/Material 由场景级资源 owner 明确释放，正常重开复用，退出/启动失败/重试后释放 |
| 帧时间 | 目标机正常档稳定 ≥30 FPS，稳态帧时间 p95 ≤33.3ms；记录采样时长，超标先优化/报告 |
| Draw call | 初始目标 ≤120，超标说明 UI/文字/多相机来源；不是直接照搬的通过证明 |
| 生命周期 | 连续重开 20 次后局内监听/替身/刚体归零并回到相同静态节点与资源持有基线 |
| 启动/包体 | 冷热启动、实际主包/引擎/资源体积分别记录；依据目标平台当时限制验收，不编造限额 |

32 Block 用小集合确定性遍历，不搞每帧规则扫描。每帧仅更新活跃效果的投影；静态牌、UI 排版在快照或 viewport 改变时刷新。性能日志用有界环形样本，不每帧刷控制台。
内存以可获得的真实指标和节点/持有者趋势报告；平台不提供 heap/GPU 值时写不可获取，不能用伪估算当显存。
